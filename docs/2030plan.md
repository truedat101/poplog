# 2030plan

Working plan for moving Pop-11/Poplog from historical footnote to a name
people find, try, and talk about.  Grounded in a codebase audit
(2026-08-09).  Shareable rendering:
<https://claude.ai/code/artifact/8f67d49d-ecb6-4ba9-99ec-8f4f8a9cd409>.
Editor-bindings detail lives in `../poplog-language-binding-plugins.md`.

**Core finding: Poplog's problem is not capability — it is
invisibility.**  The system beats CPython 3–20× on real workloads,
self-hosts on RISC-V, and carries forty years of AI teaching material.
But its documentation is invisible to search engines and LLMs, nothing
highlights `.p` files, there is no way to try it without building it,
and its most novel property — live native compilation — has no public
demonstration.

Effort scale: **S** ≈ days · **M** ≈ 1–3 weeks · **L** ≈ 1–2 months ·
**XL** ≈ quarter+.

## The unfair advantages (what everything leans on)

1. **Live native compilation** — redefine procedures in a running
   process, at machine speed; measured 3–20× CPython (BENCHMARKS.md).
2. **Five languages, one heap** — Pop-11, Prolog, Common Lisp, SML,
   plus the new native Forth, interoperating on one VM/GC.
3. **Tiny and portable** — 2.5–3.7 MB seed binaries; self-hosts on a
   RISC-V SBC; nix flake; four released corepops.
4. **Saved images** — checkpoint state + native code, restore in
   milliseconds (~190 KB / ~8 ms measured in the pop11 skill).
5. **Provenance and corpus** — the real lineage of British AI; the
   Birmingham/Sussex teaching material one `fetch-learning.sh` away.

## Tier 2 — Table-stakes standard library

Pattern set by `lib json` + `lib crypto` (2026-08, three-architecture
validation): pure Pop-11 where possible, small C shim where not,
TEACH + HELP + must-fail tests always.

| # | Item | Leverage / Effort |
| --- | --- | --- |
| 2.1 | **`lib shell`** — run with status/stderr/timeout; pipelines; background jobs. Only fire-and-forget `sysobey` exists today. | high / S |
| 2.2 | **`lib http_server`** (+ fuller client) — `unix_sockets.p` has the full accept surface but nothing above it; compose with `lib json`. Unlocks the "web service in Pop-11" story. | high / M |
| 2.3 | **UTF-8 string layer** — strings are bytes; `pop/extern/unicode` has C codecs (incl. UTF-8, EUC-JP, Shift-JIS) but no Pop-11 surface. Reuse lib json's emit_utf8 logic. | medium / S–M |
| 2.4 | **Modern regex surface** — the core engine (`src/regexp_compile.p`) has no friendly library face; wrap it or shim PCRE2 on the popcrypto pattern. | medium / S–M |
| 2.5 | **`lib test`** — formalize the check/mishaps harness used by test-json/test-crypto (74 cases) into a documented framework. | medium / S |
| 2.6 | **Quick-wins batch** — `fileutils`, `strutils`, `csv`, `datetime`; ≤2 days each; ideal good-first-issues. | medium / S each |

## A 90-day sequence

1. **Docs portal + llms.txt** (1.1) — everything else gets easier once
   the system is legible to search and AI.
2. **Tree-sitter grammar → GitHub highlighting** (1.2 / P1 of the
   bindings plan) — the repo starts looking alive.
3. **Jupyter kernel + server-backed playground** (1.3, 1.4a) —
   try-it-now exists.
4. **`lib shell` + `lib http_server`** (2.1, 2.2) — the "build
   something real" demo becomes writable.
5. **Publish the skill as an MCP server + two showcase posts**
   (3.1, 3.2) — the story ships.

Everything above is small-team-sized; the two big rocks (wasm backend,
Windows port) stay on the roadmap but gate nothing.  `README.ja.md`
(4.4 first cut) can slot in anywhere — it is independent of the rest.

## What *not* to do

* **Don't chase Python-ecosystem parity.**  Poplog wins on live-ness,
  size, and the multi-language heap.  Interop (shims, MCP) beats
  reimplementation.
* **Don't modernize away the weirdness.**  The open stack, ved, TEACH
  files — the strangeness is the story.  Frame it; don't sand it off.
* **Don't lead with benchmarks.**  Strong support, bad headline:
  "faster than CPython" starts arguments; "redefine native code while
  it runs" starts demos.
